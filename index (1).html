Script 1 — Evidence Collector

collect.py reads three system sources and saves the findings to a timestamped JSON file. Each run produces a new snapshot that can be compared against previous runs for drift detection.

Evidence collected per run:

  • Interactive user accounts from /etc/passwd (uid ≥ 1000)
  • SSH configuration from /etc/ssh/sshd_config
  • Sudo rights from /etc/sudoers

Script 2 — Baseline Checker and Drift Detector

check.py loads the two most recent evidence snapshots. It runs each finding through a set of NIST SP 800-53 rules and flags any change between runs as configuration drift.

Self-Test — Drift Detection Validated

To validate drift detection, PermitRootLogin no was deliberately added to /etc/ssh/sshd_config. A new evidence snapshot was collected and check.py was run against it.

Results confirmed:

  • AC-17 status changed from FAIL to PASS
  • Drift detection flagged: SSH CONFIG CHANGE — was: {} | now: {'PermitRootLogin': 'no'}

Detection Engineering Insights

This lab demonstrates the core loop of any configuration monitoring system: collect a snapshot, compare it to a baseline, flag what changed. The same pattern underlies enterprise tools like AWS Config, Azure Policy, and Qualys Policy Compliance — this tool implements that logic from scratch in Python.

Key engineering decisions made during the build:

  • Evidence is stored as timestamped JSON so every run is independently auditable
  • The sudoers file requires elevated privileges to read — the tool handles PermissionError gracefully and flags it rather than crashing
  • Drift is detected by comparing Python sets, which handles ordering differences between runs cleanly
  • FAIL vs WARN distinction mirrors real SOC alert severity: FAIL means a specific requirement is unmet; WARN means something exists that warrants human review
